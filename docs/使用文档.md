# 零之使魔·协奏曲 中文 ROM 构建项目 — 使用文档

> 本文档面向**没有参与过开发**的使用者：如何打包、目录里各是什么、如何修改译文与
> 图片、出错了怎么办。阅读时间约 15 分钟；只想打包请直接看 §2。

---

## 1. 这个项目做了什么

将 PS2 游戏《零之使魔 小恶魔与春风的协奏曲》（光盘编号 SLPS_257.09）的日文
全面替换为简体中文，产出一个可直接运行的汉化 ISO。覆盖四层内容：

| 层 | 内容 | 规模 | 素材位置 |
|---|---|---|---|
| 剧情文本 | SCENE_ID.BIN 里的 Squirrel 剧本源码（对白、旁白、章节标题） | 1,765 个场景文件 | `text\#####.tsv` |
| 系统文本 | 菜单、提示、确认框等 | 见 `system_map.tsv` | `text\system_map.tsv` |
| 人物名 | 对话名牌上的角色名 | 见 `speakers.tsv` | `text\speakers.tsv` |
| 战斗文本 | 技能 / 道具名与说明、角色简介 | 99 条 | `text\battle_text.tsv` |
| 界面图片 | 暂停菜单按钮、人名铭牌、人物信息界面等烘焙进贴图的文字 | 33 张 TM2 | `assets\menu_images\` |
| 音乐模式 | 曲名列表 | 30 首 | `text\elf_songs.tsv` |

### 1.1 一句话原理

游戏用一张**单色点阵字库图**显示所有文字：图集有 2,186 个格子，每格一个字符；
**码表**把「双字节字符码 → 格子号」对应起来。文本里存的不是汉字，是双字节码。
所以汉化 = ①把中文字形画进格子 ②让中文文本用对应格子的码写进剧本。
**图集尺寸和码表字节数一个都不能改**，否则游戏读不到——这是整个项目最重要的一句话。

### 1.2 字库方案（本项目的核心，详见 §5）

- **2,075 个不同汉字**中，1,312 个（63%）直接**复用原版 SJIS 码**（原版字库里
  已有这些字的格子，中文文本直接写原码，不占新槽位）；
- 763 个原版没有的字，分配**自定义码**（只用 0x81–0x87 前导段）；
- 386 个日文原字码**保留不动**（剧本里未翻译的日文借字、界面符号）；
- 全部 2,075 个字用**同一套微软雅黑字体重绘**，观感统一，无「日文字形 + 中文字形」
  混合现象；槽位余量充足，**没有为塞字库删掉任何字**。

## 2. 一键打包

### 2.1 前置条件（只需安装一次）

| 依赖 | 检查方法 | 缺失时 |
|---|---|---|
| Python 3.x | `python --version` | 安装 Python 3，勾选 Add to PATH |
| Pillow | `python -c "import PIL"` | `python -m pip install Pillow` |
| 微软雅黑 | 存在 `C:\Windows\Fonts\msyh.ttc` | Windows 简体中文版自带；缺失时改 `tools\build_all.ps1` 的 `-FontPath` |
| 原版 ISO | `rom\01.iso`（约 1.5 GB） | 已随项目附带；若删除过，把原版日文 ISO 放回该路径 |

### 2.2 打包步骤

1. 双击项目根目录的 **`一键打包.bat`**；
2. 脚本自动做完前置检查，然后开始构建（完整流程约 **20–30 分钟**，期间不要关窗口）；
3. 看到「构建成功」后，成品在：

```
output\01_patched.iso      ← 汉化 ROM（拷给 PCSX2 / 刻盘 / 实机即用）
output\build.log           ← 本次构建完整日志（出问题先看这个）
output\build\verify.log    ← ISO 自校验报告
```

### 2.3 命令行用法（进阶）

```bat
rem 完整构建（等价于双击 bat）
powershell -ExecutionPolicy Bypass -File tools\run_build.ps1

rem 跳过 ISO 打包，只做到重打包（调试用，约 3-5 分钟）
powershell -ExecutionPolicy Bypass -File tools\build_all.ps1 -SkipIso

rem 烟测：只处理 00005 号场景，快速验证管线（约 1-2 分钟）
powershell -ExecutionPolicy Bypass -File tools\build_all.ps1 -Smoke

rem 指定输出目录 / 译文目录 / 字体
powershell -ExecutionPolicy Bypass -File tools\build_all.ps1 -OutDir D:\out -TransDir D:\mytext -FontPath "C:\Windows\Fonts\simhei.ttf" -FontPx 22
```

## 4. 构建管线原理（build_all.ps1 八步）

```
原版文件 ──► [1] 解包 ──► [2] 扫描保留码 ──► [3] 收集中文用字
                                                            │
                                       [4] 槽位规划 ◄───────┘
                                            │
                                       [5] 生成码表 + 重绘字库 + 补丁曲名
                                            │
                                       [6] 注入文本（剧情/系统/人名/战斗）
                                            │
                                       [7] 重打包 NORMAL / SCENE_ID
                                            │
                                       [8] 重建 ISO + 自校验
```

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| 1 解包 | 从 `base\` 的纯净 .BIN/.HD 解出全部场景剧本与字库文件 | 用游戏自带压缩算法（codec.cs）解压 |
| 2 扫描保留码 | 统计未翻译场景/系统文本仍在用的日文码 | 这些码的格子**必须保护**，不能被中文占用 |
| 3 收集用字 | 从译文 + 人名 + 系统文本 + 战斗文本 + 曲名统计全部不同汉字 | 得 2,075 字 |
| 4 槽位规划 | 每个字决定「复用原版 SJIS 码」还是「分配自定义码」 | cp932 能编码且原表有格子的 → 复用；否则 → 自定义 |
| 5 码表+字库 | 生成 `encoding_map.txt`，码表全局升序重排，用微软雅黑统一重绘全部涉及格子 | 产出 `output\build\font_preview.png` 可肉眼检查 |
| 6 注入文本 | 按 TSV 改写剧本源码：对白、说话人名、系统串、战斗定长表 | 战斗表是定长字节替换，译文超长会报错 |
| 7 重打包 | 把改过的条目重新压缩回 NORMAL.BIN / SCENE_ID.BIN | 未改条目原样保留 |
| 8 重建 ISO | 复制原版 ISO，覆盖四个文件；体积变大的重定位到镜像尾部并改目录记录 | 更新 PVD 卷大小，随后自校验 |

自校验（verify_iso.ps1）做四件事：四个目标文件按新目录记录读回与构建产物 MD5 一致；
PVD 卷大小与实际文件大小一致；其余 49 个未动文件与原版 ISO **逐字节一致**；
其中 SLPS_257.09 的差异是预期的（曲名补丁，见 §4 注）。

> **注**：verify.log 里 `DATA DIFF: SLPS_257.09 at byte 1138796` 与
> `untouched files checked: 49, bad: 1 FAIL` 是**预期输出**——该行的本意是
> 「除曲名补丁外无意外改动」。曲名补丁位于 ELF 0x116068 起的 30 个槽位，
> 构建日志里对应 `patched 30/30 titles`。

## 5. 字库方案详解

### 5.1 三套码的关系

| 类别 | 数量 | 存放 | 说明 |
|---|---|---|---|
| native 复用 | 1,312 | 文本直接写原版 SJIS 码 | 原版字库已有格子，零新增槽位 |
| 自定义码 | 763 | `encoding_map.txt` | 原版没有的字，占用空闲格子 |
| 保留日文码 | 386 | `retained_codes.txt` | 未翻译的日文借字 / 界面符号，格子冻结 |

### 5.2 为什么不会「爆字库」

字库图集格子总数固定。本项目把 63% 的汉字分流到「原版格子」，自定义码需求
从 1,525（早期方案，超出容量导致构建失败）降到 763，槽位余量充足。
槽位规划有一条**铁律**（写在 build_all.ps1 里）：

> native 字的格子绝对不能再分配给自定义字。否则该字的码从码表里消失，
> 游戏二分查找失败，显示成回退字形「、」——这正是早期版本截图里满屏
> 「、」的根因。因此可用槽 = 全部格子 − 保留码占格 − native 独占格。

### 5.3 编码产物（每次构建生成于 output\build\）

| 文件 | 内容 |
|---|---|
| `encoding_map.txt` | 自定义码：汉字 TAB 四位十六进制码 |
| `native_reuse.txt` | 复用码：汉字 TAB 原版 SJIS 码 |
| `retained_codes.txt` | 保留的日文码列表 |
| `injected_slots.txt` | 每个自定义字落在图集的第几行第几列 |
| `font_preview.png` | 重绘后的字库预览图（检查字形用） |

### 5.4 想改字形 / 字体 / 字号

改 `tools\build_all.ps1` 的参数后重跑一键打包即可：

- `-FontPath`：渲染用字体（默认微软雅黑 `C:\Windows\Fonts\msyh.ttc`）
- `-FontPx`：字号（默认 22）

字库图集是 24×26 点阵格，字号过大会糊、过小会缺笔画，建议 20–24 之间调。

## 6. 如何修改译文

### 6.1 场景剧本（text\#####.tsv）

三列 TSV，**一行为一条台词**：

```
编号 <TAB> 日文原文 <TAB> 中文译文
```

- 换行用两个字面量 `\n` 表示（不是真实换行符）；
- 只改第三列；第一列编号与剧本调用顺序一一对应，**不要增删行**；
- 日文列是校对用的，改不影响构建；
- 译文长度没有硬限制（剧本字符串是变长的），但单行过长在游戏里会超出对话框，
  以实机测试为准。

### 6.2 系统文本 / 人名 / 战斗文本

两列 TSV：`日文 <TAB> 中文`，按原文精确匹配替换。

- `system_map.tsv`：菜单与提示语；
- `speakers.tsv`：角色名（写进对话名牌，也参与全局串替换）；
- `battle_text.tsv`：技能/道具/简介，**定长字节表**——中文编码后字节数必须
  ≤ 日文原文字节数，超了构建会报 `battle overflow`，需改短；
- `elf_songs.tsv`：三列（编号/日文/中文），音乐模式曲名，每个槽位 0x80 字节。

### 6.3 改完如何生效

改完任意 TSV，重跑 `一键打包.bat` 即可。构建是全量的：码表会按新译文重新
统计（新增的字会自动安排槽位），无需手工维护编码表。

> 注意：新增汉字若超出字库余量，构建第 4 步会明确报
> `charset exceeds capacity` 并给出需要替换多少个低频字——按提示替换
> （如「馳」改用已有同义字）或删减未使用译文即可。

## 7. 如何修改图片素材

### 7.1 素材是什么

33 个 TM2 贴图是**已经把中文「烘焙」进图片**的界面资源：暂停菜单按钮
（演奏开始 / 返回 / AUTO PLAY 等）、对话人名铭牌（露易丝、才人…）、
人物信息界面（魔法列表、好感度条、持有数标签）、以及「你输了……」等横幅。
`assets\preview\` 里有 14 张效果图可人工核对；`assets\textures_manifest.csv`
是 NORMAL.BIN 全部 360 个图片条目的总清单（含尺寸、位深、汉化状态）。

### 7.2 替换一张图

1. 从原版 ISO 的 NORMAL.BIN 取出同名条目（或用现有 TM2 反编译）；
2. 用 PS2 TIM2 工具改图（保持尺寸、位深、调色板结构不变）；
3. 覆盖 `assets\menu_images\` 下的同名文件（如 `00051.tm2`）；
4. 重跑一键打包——第 7 步会自动把它打进 NORMAL.BIN（日志里
   `ui textures: 33 entries`）。

> 改图不在本工具链范围内（需要 TIM2 编辑器）；本仓库负责「把改好的图
> 正确打进 ROM」。构建只认文件名与条目号的对应，不校验图片内容。

## 8. 存档标题乱码（旧记忆卡）

读档界面章节标题乱码**只影响旧存档**：早期构建写入的存档用的是当时的码位，
与最终版码表有出入（如旧码 `8CA8`=「託」，最终版 `8CA8`=「肩」）。
最终版 ROM 新存的档标题本来就正确。

修复工具：`fix_save_titles.py`

```bat
python fix_save_titles.py --scan     :: 扫描报告（只读，不动数据）
python fix_save_titles.py            :: 按内置修复表重写 + 自动备份 + 写后校验
```

详见 `docs\存档标题修复说明.md`。修复后需在 PCSX2 退出到 PS2 浏览器或重启
一次模拟器再进读档界面查看。

## 9. 常见问题（FAQ）

**Q：一键打包报「找不到原版 ISO」**
把原版日文 ISO 放到 `rom\01.iso`。注意是**日文原版**，不是别的汉化版。

**Q：报 `charset exceeds capacity`**
译文引入了过多新字。按日志提示替换低频字（用同义已有字），或删减未使用译文。

**Q：报 `battle overflow: XXX`**
该条战斗文本中文编码后比日文长。把译文改短（定长表装不下）。

**Q：字库预览里某个字是空白/豆腐块**
说明渲染字体缺该字形（生僻字）。换覆盖更全的字体（如方正宋体大字符集），
或把该字替换成常用同义字。

**Q：构建中途报 python 相关错误**
确认 `python -c "import PIL"` 能跑；一键打包.bat 已做前置检查。

**Q：想确认 ROM 没被改坏**
看 `output\build\verify.log`：四个文件 MD5 全部 OK、PVD OK、未动文件 0 差异
（SLPS_257.09 的预期差异见 §4 注）。

**Q：PCSX2 里读档/存盘异常**
先用 §8 的工具修旧存档；仍异常就用没改过的记忆卡新建档测试。

**Q：项目想换目录 / 换电脑**
整个文件夹拷贝走即可，无硬编码路径；记得目标机装好 Python + Pillow。

## 10. 复现与校验

构建是**确定性**的：同一套 `text\` + `assets\` + `base\` + `rom\`，
任何时候重跑都得到逐字节一致的 ISO。一次完整构建的实测参考值：

| 文件 | MD5 |
|---|---|
| `output\01_patched.iso` | `50bea006cc8bdd679f1e830d13d76f99`（1,572,055,040 字节 / 767,605 扇区） |
| `output\build\NORMAL.BIN` | `456953ad8b9621aeb5336123830b4445` |
| `output\build\SCENE_ID.BIN` | `dac4ec3db2f2befb4c5fda6c75db7c71` |
| `output\build\SLPS_257.09.bin` | `310fd04c732902cca90736482ac4f92a`（含 30 首曲名补丁） |

构建过程中的关键数字（与参考值一致即说明流程正确）：保留码 386、
总用字 2,075 = native 1,312 + 自定义 763、空闲槽 765、注入 1,796 个剧本文件 /
17,277 行对白 / 17,173 处人名 / 1,878 次系统串、战斗文本 99 条、界面贴图 33 张。

想核对 `base\` 未被改动：运行 `powershell -File tools\extract_base.ps1`
从 `rom\01.iso` 重新抽取，MD5 应与现有文件一致（SLPS_257.09.bin
参考值 `e42e4f072bd40cab20c8e47a0107e9d1`）。
